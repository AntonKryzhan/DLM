# Исправления 2.1 по вашему отчёту

Архив `DPI-diagnostics-20261118-213402.zip` прочитан полностью. В четырёх
сеансах нет ошибок отправки/приёма WinDivert; каждый сеанс завершился с кодом 0.
Это не означает успешный обход.

В журнале есть 640 событий преобразования пакетов, из них **423** относятся
к DNS через HTTPS: Cloudflare, Google DNS и другим распознанным DNS-хостам.
Прежний автоматический режим применял стратегии слишком широко. Сбой такого
соединения может мешать браузеру открывать и российские, и зарубежные сайты.
Это установленное поведение кода; считать его единственной причиной всех
отказов по этому отчёту нельзя.

Также найдена и исправлена ошибка: после достижения лимита новых cover-пакетов
мог сработать старый генератор fake TCP/RST. Теперь ручной генератор вызывается
только при явно отключённом автоматическом подборе. Добавлен тест повторной
отправки после лимита, с включёнными старыми настройками.

## Автоматическая обработка

- GUI всегда передаёт `--automatic`, независимо от старых переключателей INI.
  Командная строка и ручные профили остаются для совместимости.
- Окно сервера, SYN, UDP, QUIC и локальные адреса в этом режиме не изменяются.
  Известные DNS-over-HTTPS хосты исключены из преобразований.
- YouTube/CDN и Discord распознаются по имени TLS/HTTP. Для остальных хостов
  сначала наблюдается исходное соединение. Две независимые ошибки ответа TLS
  могут включить подбор на следующих соединениях. Отсутствие SYN-ACK,
  отмена клиентом и HTTP-ошибка не считаются основанием для такого включения.
- Если шесть преобразованных соединений подряд не дают результата,
  преобразования для этого имени приостанавливаются на две минуты.
- Статистика выбора привязана к имени, адресу, порту и интерфейсу: успешный
  соседний сайт на общем CDN не определяет стратегию для другого имени.
- Обучение действует только в памяти текущего сеанса. Настройки DNS, proxy,
  маршруты, firewall, службы и настройки VPN программа не меняет.

## Интерфейс

Панель настроек заменена тёмным окном с карточками, крупным состоянием,
одной кнопкой включения/отключения и действиями «Проверить сеть», «Собрать отчёт»,
«Открыть журнал». Готовность движка проверяется по событию, а не факту запуска EXE.
При закрытии GUI движок получает сигнал остановки; если GUI аварийно завершится,
движок обнаружит завершение родительского процесса и снимет перехват.

Перед включением проверяются HTTPS-ответы от `ya.ru`, `mail.ru` и Wikipedia
при остановленном NoDPI. Достаточно ответа одного контрольного узла. Если
ни один не отвечает, GUI не запускает перехват и предлагает сетевую диагностику.
Ответ 2xx–4xx здесь означает достижимость HTTPS, а не проверку содержимого страницы.

## Что остаётся неизвестным

В снимке после остановки NoDPI есть процесс AdGuard VPN и работающая служба
AmneziaVPN. Их наличие не доказывает активный туннель или включённый Kill Switch.
В отчёте нет исходной проверки DNS/TCP/HTTPS при остановленном движке, поэтому
невозможно отделить влияние VPN, proxy, DNS, другого фильтра и провайдера.
В HTTP-пробе Discord Gateway API и Wikipedia ответили, YouTube и страница
Discord завершились тайм-аутом; время этой пробы не доказывает состояние сети
после последующего отключения программы.

Новая «Проверить сеть» отдельно записывает системное разрешение имён,
прямой TCP, HTTPS, proxy, маршруты и наличие VPN-процессов. Отчёт помечает,
работал ли NoDPI во время измерения. Никакие службы или фильтры не отключаются.
После проверки с выключенным VPN и выключенной обработкой соберите новый ZIP.

Официальные основания:
[AdGuard VPN: Kill Switch](https://adguard-vpn.com/kb/adguard-vpn-for-windows/overview/),
[WinDivert: shutdown и освобождение handle](https://reqrypt.org/windivert-doc.html).
Kill Switch способен блокировать интернет при потере VPN; его состояние нужно
проверять в самом VPN-клиенте, а не определять по списку процессов.

# NoDPI DLM 2.4 — MWO/CDN и диагностика запуска

В этом обновлении **нет готовых EXE**. Оно устанавливается поверх 2.3;
пользовательский config.ini, списки и драйвер не заменяются.

## Собрать и запустить

1. Закройте старый GUI и движок NoDPI.
2. Содержимое папки **DPI** из архива скопируйте в
   `M:\users\Ark\Desktop\DLM\DPI` с заменой файлов.
3. Запустите **Build-And-Run.cmd**. Он выполнит тесты, соберёт четыре программы
   и откроет GUI только после успешной сборки.
4. Нужен прежний SDK **DLM 0.133.0+** и x64 MinGW GCC. По умолчанию SDK ищется
   в соседней папке `..\DLM-OUT`; также поддерживается DLM_SDK.

Если SDK находится в другом месте:

```powershell
.\Build-And-Run.cmd -SdkPath "M:\путь\DLM-OUT"
```

Отдельная сборка — Build.cmd, только тесты — Test.cmd.
В build-local.json записываются фактические версии и хеши собранных программ.
При ошибке смотрите build\build.log: старые EXE заменяются после успешной сборки
всех новых. GPU, модель нейросети, Python и загрузка внешних движков не требуются.

## Найти стратегию

1. Отключите VPN. В списке сервиса выберите **Telegram Web + Desktop**
   (или другой нужный сервис), нажмите **«Обучать 10 минут»**, подтвердите UAC.
   Свой обычный движок GUI предварительно остановит.
2. В окне видны число кандидатов, поколение, идентификатор лучшего метода,
   доля пройденных целевых проб, контроль, прошедшее время и индикатор бюджета.
3. Поиск сравнивает методы с запуском без обработки и отдельно перепроверяет
   найденное улучшение. Если сайт уже доступен без NoDPI, это не объявляется
   успехом алгоритма. Если нет подходящего наблюдения преобразований, процент
   не выдаётся за подтверждённый результат.
4. Кнопка превращается в **«Остановить поиск»**. Отмена снимает перехват
   своего тестового движка. Закрытие GUI также прекращает поиск.
5. Только подтверждённое улучшение автоматически сохраняется в active.profile.
   При отсутствии улучшения прежний активный профиль остаётся. Нажмите
   **«Включить»**, чтобы применить активный профиль в обычном режиме.

Параметры и генетические операции реализованы на DLM. PowerShell организует
Windows-процессы и измерения. Предлагаются новые комбинации разрезов, порядка,
одинакового перекрытия и защищённых cover-пакетов. Исходный TCP/TLS-поток
не заменяется другими данными. Подробности и разбор обоих новых отчётов —
**CHANGES_2.2_RU.md**. Изменения Telegram и порядок проверки —
**CHANGES_2.3_TELEGRAM_RU.md**.

Изменения MWO, Cloudflare, CloudFront, Azure и разбор ошибки запуска
WinDivert 58 — **CHANGES_2.4_MWO_STARTUP_RU.md**. Для MWO в списке сервиса
выберите **MWO + CDN / Cloudflare / Azure**. После ошибки запуска кнопка
**«Проверить драйвер»** открывает Check-Driver.cmd с запросом UAC.

В media-url.txt домены MWO/CDN добавлять не нужно. После включения
перезапустите клиент MWO и проверьте вход. **Check-MWO.cmd** проверяет
публичные HTTPS-ресурсы, затем 90 секунд наблюдает адреса TCP-соединений
MWOClient/MWOPortal; в это время выполните вход вручную.


## Проверить Telegram

После сборки включите обработку и полностью перезапустите Telegram Desktop
(в том числе завершите его из трея). Перезагрузите вкладку Web A/K.
Необходимо новое TCP-соединение: существующие MTProto-потоки не изменяются.

**«Проверить сервис»** при выбранном Telegram запускает **Check-Telegram.cmd**.
Отчёт проверяет страницы Web A/K и публичный обмен req_pq_multi → resPQ по
обфусцированному TCP и WSS. Полная диагностика охватывает DC1–DC5 и порт 5222;
быстрый вариант — `Check-Telegram.cmd -Quick`. Вход в аккаунт не выполняется,
`tdata` не читается. Доступность переписки, медиа и звонков проверьте вручную.

**media-url.txt предназначен только для YouTube-видеопотока.** Telegram туда
добавлять не надо. Домены и официальные IPv4/IPv6 сети включены в патч.
Если в самом Desktop настроен недоступный прокси, выключите его для проверки
прямого подключения: программа не меняет настройки Telegram.

При подборе видны отдельные результаты TG Web и Desktop. Новый профиль
Telegram действует на Telegram, остальные известные сервисы продолжают
использовать автоматический выбор. Старые профили с Target=0/1/2 читаются.

## Что означает эффективность

Число вроде 5/5 — результат перечисленных проб в текущем испытании.
Используются WinHTTP HTTP/2 и HTTP/1.1. При наличии Chrome/Edge дополнительно
проверяется страница YouTube в отдельном временном headless-профиле без
системного HTTP proxy. Ваши браузерные профили не читаются и не изменяются.
Проба DOM может не пройти из-за CAPTCHA/consent и не проверяет воспроизведение.

Для проверки видео-CDN поместите актуальный HTTPS URL видеопотока в UTF-8 файл
**media-url.txt** в папке DPI. Проба читает до 1 МиБ и должна получить не менее
64 КиБ; URL с 403/401/410 требует обновления, а не объявления нового обхода.
Содержимое этого файла и query-параметры не включаются в отчёт. Само получение
URL и вход в YouTube не автоматизированы. Без файла GUI явно показывает
**«видео не проверено»**. Голос Discord требует ручной проверки.

После подбора проверьте видео в обычном браузере не менее двух минут.
Найденная HTTP-стратегия не является гарантией работы всех видео, голосовых
соединений, браузеров, провайдеров и ТСПУ.

## Сохранение и загрузка

- **«Сохранить профиль»** открывает диалог и сохраняет параметры вместе
  с результатами, временем и контекстом испытания. Неподтверждённый кандидат
  тоже можно сохранить отдельно: его статус остаётся неподтверждённым.
- **«Загрузить профиль»** проверяет Schema=1 и диапазоны параметров, сохраняет
  копию прежнего active.profile и устанавливает выбранный файл. Профиль
  применяется при следующем включении обработки.
- После загрузки GUI помечает оценку как полученную из файла. Это не новое
  измерение на текущем подключении. Повторное обучение перепроверяет стратегию.

## Отчёт и ограничения

**«Проверить сеть»** измеряет DNS/TCP/HTTPS и записывает состояние proxy,
адаптеров и маршрутов. **«Собрать отчёт»** упаковывает JSONL движка, результаты
поиска и браузерных проб, training.status, профиль и сведения о вашей сборке.
После испытания пришлите полученный DPI-diagnostics-....zip.

Журналы содержат домены и сетевые адреса. Тела HTTP, DOM браузера, cookie,
пароли, личные профили браузера, VPN-ключи и media-url.txt не собираются.
Настройки DNS, proxy, firewall, VPN, маршрутов и служб Windows не меняются.

Исправлены раннее прекращение разбора составного ClientHello и отсутствие
адресного QUIC fallback в автоматическом режиме. Проверки кода описаны в
**VALIDATION_RU.md**. Само обновление, GUI, headless-пробы и эффективность в вашей
Windows/сети здесь не запускались; это предстоит измерить локальной сборкой.

# v0.99 — Source identity and physical diagnostics

This is a bounded A/B engineering step, under laws 11–13, 22, 30, 39–42.
It preserves the source of executable expressions across imports and lowering.
It does not close all of A/B or the C-min acceptance gate.

## Source context

`SourceSpan` contains a compilation-local `FileId`, start/end line and
start/end column. Lines and columns are 1-based, columns count UTF-8 bytes,
and the end is exclusive. A line-only span uses zero columns. Existing
`line`, `line_col` and `new` constructors use `FileId::ROOT`; `with_file`
sets an explicit identity. Their existing position-only Display is retained.

`SourceFile { id, path: Option<PathBuf> }` identifies an input in one
compilation. `Module::source` and `ResolvedModule::source` carry it.
`parse_module(source)` retains anonymous, in-memory behavior.
`parse_module_with_source(source, file)` records the supplied context on
expressions and parse errors. Expression clones keep their IDs and spans;
structural expression equality still ignores those metadata.

`link_program` and the file loader assign distinct IDs in dependency order;
the root uses ROOT and dependencies use 1, 2, etc. Only reachable modules
are included. Library-list order does not affect these IDs. Rebinding
updates all expression spans, including statements and nodes generated by
desugaring, while preserving ExprIds, physical positions and source paths.
IDs are not serialized package identities, content hashes or filesystem
inodes. Paths retain the loader's spelling rather than being canonicalized.
Clones of a module keep their context until linked into a new program.

The pre-1.0 Rust AST/facts/IR/Diagnostic structs gain source-metadata fields.
Rust callers using struct literals must supply those fields; existing parser,
checker and SourceSpan constructor entry points remain available. DLM source
syntax and the native C ABI remain unchanged.

## Diagnostics

The parser maps logical-line error positions back to original physical
lines and undoes text-literal placeholders exactly once. Errors from the
literal-masking pass already have physical coordinates and are not remapped.
Successful expression spans keep the previous v0.87 mapping.

The checker and lowering attach the innermost expression's precise span
to a legacy line-only error. Propagation through enclosing calls and operators
preserves an already precise span. Diagnostics from imported or inherited
function bodies resolve their paths by the original FileId. The CLI's
single-module fast path supplies source context too.

Named diagnostics display `at path:line:byte-column`; line-only diagnostics
display `at path:line`. Diagnostics without a path retain the previous human
format, and `Diagnostic::line` still equals the primary physical line.
Error kinds, codes, help text and exit statuses retain their meanings.
Diagnostics without a known position can still carry a path.

## Checked facts and IR

TypedFacts records every AST expression's span, including named callbacks
checked through collection contracts, and ordinarily inferred types by ExprId; inconsistent
types or spans mark a conflict. Function and record facts carry their
declaration's line span and FileId. Lowering refuses a source expression
whose span differs from its checked fact. Checked record spans pass into
record layouts rather than being rebuilt with a default file ID.

`IrProgram::sources` maps file IDs to source paths. `source_spans` retains
the checked expression-location map, without AST expressions, passports
or proof objects. Every IR node keeps its span and optional origin ExprId;
synthetic initializer calls have no origin and use their source construct's
span. Before backend emission, `verify_ir` rejects:

- missing or duplicate source file identities;
- an unknown file ID or invalid physical range in a record, expression or initializer;
- a non-synthetic origin absent from the checked map or paired with a different span.

The human-readable `DLM-IR v3` listing retains its existing header and
operation syntax; it adds a source-file table and a source-location line
per function. It remains a diagnostic listing, not a serialized IR ABI.

These are metadata consistency checks, not a proof that the compiler is
correct. A caller that forges both the source table and all corresponding
checked metadata is outside this guarantee. Source paths and spans confer
no StaticProof, machine-definedness or optimization authority. Evaluation
order, machine arithmetic, effects, runtime representation and C ABI do not
change in this step.

## Validation and remaining work

`source_identity.rs` covers named and anonymous inputs, UTF-8/CRLF,
literal-mask lengths, multiline errors, parser-context isolation, diamond
imports, distinct IDs, original imported error locations, declaration and
resolution failures, inherited records/functions, lambdas/match/initializers,
stale checked facts, unsupported wide literals and corrupt IR metadata.
`cli_source_locations.rs` covers root/dependency error locations, the
single-file fast path, failed compilation before output creation and a
native imported program producing `42`.

The existing diagnostic, Typed Core, module, record and interpreter/C
regressions remain required. Test commands are in `TEST_MATRIX.md`.
Validation targets Linux x86-64, Rust 1.99.1 and GCC; Windows validation
is still open. For the full arithmetic stress suite, the test profile may
use opt-level=2 with overflow checks and debug assertions enabled.

`cargo clippy --workspace --all-targets --locked --offline` completes with
warnings. In addition to the existing style warnings, source metadata makes
Diagnostic reach Clippy's large-error threshold, so by-value Result APIs
produce `result_large_err` warnings. This is retained explicitly rather than
changing unrelated error APIs or suppressing the lint. It does not alter
native DLM values or numerical resource budgets.

The function/record fact handoff left open by v0.99 is addressed in v0.100
(`DECLARATION_IDENTITY.md`). Remaining A/B work includes full HIR/MIR and
moving all value/call/local/constructor reference resolution before lowering. Declaration
and research-layer errors can remain line-only; exact identifier token
spans for all declarations/imports are not introduced. Runtime failures
retain their existing reporting, and native binaries do not yet embed
source maps or debugger information. Filesystem API, ownership, dense
buffers, FFI, networking and the full proof kernel retain their open gates.
The mathematical queue remains at N01–N06 closed, N07–N16 open.

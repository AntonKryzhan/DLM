# Сборка самостоятельного DLM для Windows x64

Этот архив содержит сборщик. Готовый Windows-комплект будет создан на вашем
компьютере после успешного запуска `Build-DLM.cmd`.

1. Распакуйте архив в отдельную папку.
2. Запустите `Build-DLM.cmd` обычным двойным щелчком.
3. Дождитесь зелёной строки `READY`.
4. Откройте `M:\users\Ark\Desktop\DLM\DLM-OUT\DLM-Shell.cmd`.

Заданы ваши пути:

- Исходники: `M:\users\Ark\Desktop\DLM\DLM-main`.
- Готовый комплект: `M:\users\Ark\Desktop\DLM\DLM-OUT`.

Если исходники находятся в `DLM-main.zip`, сборщик обнаружит его по этому же
пути. Поддерживается папка с `Cargo.toml` или ZIP с одной вложенной папкой проекта.
Собирается именно найденная версия исходников; новые патчи автоматически
не применяются. Нужна полная сборка исходников с `lib`, а не отдельный патч.

При первом запуске нужен Интернет: сборщик загрузит переносимый WinLibs GCC и
изолированный Rust GNU. Загрузки проверяются по SHA256. Rust используется для
сборки самого DLM; в готовый SDK он не входит. Повторные сборки используют кэш
`%LOCALAPPDATA%\DLM\BuildCache`. Установка Visual Studio не требуется.
Глобальный PATH, существующий Rust и системные настройки не изменяются.
Права администратора не нужны; диск M: должен быть доступен тому пользователю,
который запускает сборщик.

В `DLM-OUT` появятся:

- `bin\dlm.exe` — собранный компилятор/интерпретатор DLM;
- `dlm.cmd` — запуск DLM с автоматическим подключением библиотек и C-компилятора;
- `DLM-Shell.cmd` — командная строка для разработки;
- `lib\` — все библиотеки из ваших исходников;
- `toolchain\mingw64\` — полный переносимый C-компилятор с его файлами;
- `examples\`, `docs\` — примеры и документация из ваших исходников;
- `projects\Hello\` — первый проект и проверенное приложение `Hello.exe`;
- `VERSION.txt`, `build-info.json` — фактическая версия и результат сборки.

В текущем DLM библиотеки поставляются как модули `.dlm`: нужные модули
компилируются вместе с приложением. После создания SDK исходники компилятора,
Cargo и Rust не нужны для обычной разработки. Папку `DLM-OUT` можно переносить
целиком на другой компьютер Windows x64. Используйте `dlm.cmd` или DLM-Shell,
чтобы импорт библиотек и сборка работали из любой рабочей папки.

Сборщик сначала создаёт отдельный комплект, проверяет `check`, `run`, `build`
и запускает полученный Hello.exe с системным PATH, без Rust и GCC в PATH.
Только после успешной проверки он публикует `DLM-OUT`. Существующий `DLM-OUT`
сохраняется рядом с суффиксом `.previous-...`; папка `projects` переносится
в новый комплект. Не переименовывайте и не перемещайте исходники во время сборки.

## Первый запуск приложения

В DLM-Shell:

```bat
dlm --version
dlm check Hello\main.dlm
dlm run Hello\main.dlm
dlm build Hello\main.dlm -o Hello\Hello.exe
Hello\Hello.exe
```

Либо откройте `projects\Hello\Build.cmd`, затем `Run.cmd`.
Для своего приложения создайте отдельную папку в `projects` и файл `main.dlm`.

Для других путей:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-DLM.ps1 -SourcePath 'D:\DLM\DLM-main' -OutputPath 'D:\DLM\DLM-OUT'
```

Для полного набора тестов перед сборкой добавьте `-RunTests`. По умолчанию
выполняется проверка рабочего SDK и первого приложения, а не весь набор тестов.
Лог каждого запуска сохраняется в `%LOCALAPPDATA%\DLM\BuildCache\build-*.log`.
При ошибке готовность не заявляется, а существующий комплект сохраняется.

Здесь проверены синтаксис в PowerShell 7.6.9 на Linux, обработка ошибок,
структура ZIP и пример DLM в интерпретаторе и нативной Linux-сборке. Сборку
Windows и запуск Windows EXE выполняет скрипт на вашем компьютере: в среде
подготовки этого архива нет доступа к диску M: и Windows.

Источники инструментов: [Rustup для Windows](https://rust-lang.github.io/rustup/installation/windows.html),
[WinLibs](https://winlibs.com/),
[зафиксированный выпуск GCC](https://github.com/brechtsanders/winlibs_mingw/releases/tag/15.2.0posix-13.0.0-msvcrt-r2).
